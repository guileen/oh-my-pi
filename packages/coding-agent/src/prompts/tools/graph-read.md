Read Graph definitions, built-in headless Bot-host workflows, authoring receipts, or authorized Run observations. Use version 1 with `operation`. Discovery and definition reads take no Run authorization; Run reads require trusted host authorization and are denied when unavailable.

- `templates` — bundled example Graphs shipped with this installation, each with the same contract shape as `catalog` plus its `path`. Takes no `target_id` and grants no authority. Use it when the task has no stored Graph yet: pick a template by name, then `import` it with `{template}`.
- `workflows` — built-in headless Bot-host workflows (including `daily-code`) with exact input contract, permission boundary, entry command, exit codes and replay semantics. Takes no `target_id` and grants no authority. `templates` also advertises these separately in `workflows`; they are not Graph definitions and cannot be imported or dispatched as a DAG.
- `catalog` — every stored Graph with its declared input/output contract, definition revision, `bindings` model-binding file (a session-workspace-relative path; absent when undeclared) and `local_run` support. Takes no `target_id`. Start here when choosing which Graph accepts a task, and pass the entry's `bindings` and input names to `dispatch` instead of guessing a bindings path.
- `definition.get` — full definition text; optional `revision`.
- `request.get` — authoring or execution receipt by request key.
- `runs` entries carry `hold_kind` while held (`operator` = resumable by you, `gate` = needs a decision ref) — Run index: id, title, graph, state, `nodes:<settled>/<total> current:<node>`, last event, last activity, `stalled`. Each entry also carries `nodes[]`: per-node state in definition order with `pending` for unstarted work, `current` on the one node executing or waiting now, and optional `turns`/`last_activity_at`/`summary`. Takes no `target_id`; unauthorized Runs are omitted.
- `status` — one Run snapshot.
- `report` — the human deliverable for one Run, judged only from committed facts: title, state, declared deliverable (`ready` plus missing artifacts), per-artifact metadata with a bounded text preview, recent notifications and factual `next_actions`. Requires `target_id`. Prefer this over dumping artifact bodies or re-reading `status` plus `events`; `ready` means the declared package exists, not that anyone accepted it.
- `events` — optional `after` cursor and `limit` (1–100, default 50); continue with `next_cursor`.
- `notifications` — durable dispatch outbox: `since` (exclusive cursor, default 0), `limit` (1–200, default 50), optional `run_id`. Returns `notification_cursor`; pass it back as `since` to read only newer records. A notification means the Run reached a reportable state; it does not mean a consumer received it.
- `wait` — block this one turn on a Run until it is terminal or the first notification for it commits, whichever comes first. Requires `target_id` and an optional `timeout_ms` (1000–600000, default 60000); `since` defaults to the current outbox head, so it reports only what happens next (`since: 0` replays old records). Resuming a Run is your own control command and is not a notification: a dispatcher never wakes on its own echo. It returns the snapshot plus any new notifications and never changes the Run. Prefer `wait` over repeated `runs` polling after `dispatch`; poll again only when the wait times out and the work still matters.

A `derived` contract means the author declared none and the fields were inferred. `local_run.supported` reports foreground local runner support only; another host performs its own check. Errors are not empty results.
